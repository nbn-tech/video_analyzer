# データベースサイトの構想

## やりたいこと

チョコサムの全放送回について、超町人ごとに次のことを一覧・検索できる社内サイト。

- サムネ、名前・年齢、特徴（ジャンル）、ロケ内容の概要、ロケ地・取材場所、取材タレント、放送回・放送日
- その超町人の放送区間から動画を再生
- その超町人を放送していた時間帯の視聴率の推移（将来）
- 名前・ジャンル・放送回・ロケ地・タレントでの検索・絞り込み

## 構成の方針

データは全回で約1,100行と小さいので、**最初はサーバーもデータベースも置かず、静的なサイトにする**。
動画は S3 に上げず分析用PCに置いたまま、**分析結果だけを専用の非公開バケット `chocosamu-data` に上げる**（2026-11-19 決定）。

```
分析用PC  D:\Projects\チョコサム分析\過去動画\過去回\#NN\*.mp4（動画はここだけ。元は Dropbox）
   │  find_thumbnails.py → samunet_probe.py → samunet_summarize.py
   │  （人が名前・ジャンルを確認・修正）
   │  build_site_data.py
   │  upload_results.py（IAM ユーザー chocosamu-uploader）
   ▼
s3://chocosamu-data/   ※非公開・バージョニング有効・東京リージョン
   results/<回3桁>/rows.json, rows.csv, prompt.txt, name_frames/, thumbs/
   site/data.json, all_rows.csv, thumbs/<回3桁>/thumb_XX.jpg
   │
   ▼
CloudFront（OAC で site/ だけ読む）＋ ログイン ──▶ 社内サイト
```

### AWS の構成（決定済み）

| もの | 設定 |
|---|---|
| バケット | `chocosamu-data`（ap-northeast-1、汎用、ACL 無効、**パブリックアクセスをすべてブロック**、バージョニング有効、SSE-S3） |
| アップロード用 IAM ユーザー | `chocosamu-uploader`。インラインポリシーで `chocosamu-data` の List / Get / Put / Delete だけ。分析用PCの AWS CLI にプロファイル `chocosamu-uploader` として登録済み |
| サイト用の読み取り | 未作成。CloudFront の OAC から `chocosamu-data/site/*` だけ GetObject を許可するバケットポリシーを足す想定 |

### bangumi-info を使わない理由

video_analyzer の `bangumi-info` は、バケットポリシーで `Principal: "*"` に GetObject を許可しており、URL を知っていれば誰でも読める（2026-11-19 確認）。ダッシュボードがブラウザから `rating/`・`epg-all/`・`inout/` を認証なしで読んでいるため、すぐには閉じられない。一般の方の名前・顔を含むチョコサムのデータは、ここに置かない。

### 動画を S3 に置かない理由と、あとで再生機能を付けるとき

- 分析には不要（分析用PCのローカルファイルを読む）。完パケ・配信版は計365GB、S3 標準で月1,400円程度かかる。
- サイトで再生したくなったら、720p 程度に軽くした版（約1GB×126本、月450円程度）を `chocosamu-data/videos/` に置き、CloudFront の署名付き URL で配信する。
- 動画は2種類ある。**完パケ**（約59分、CM 部分が黒）と **配信版**（約47分、CM を抜いたもの。「_黒なし」付きとなしの差は数秒）。視聴率と結びつけるには完パケが扱いやすい。配信版は各回のフォルダの `〇〇_CM.txt`（CM の挿入位置）と CUE シートで放送時刻に戻す。

### 段階1：見られるようにする

- サイトは S3＋CloudFront の静的ページ。`data.json` を読み込み、検索・絞り込みはブラウザ内で行う（1,100行なら十分速い）。
- 動画は、超町人の開始秒から再生（CloudFront の署名付き URL）。
- **ログイン必須**（一般の方の顔と名前を扱うため）。Cognito か、社内の SSO。
- 名前・ジャンルの修正は、最初は CSV／スプレッドシートで直して `data.json` を作り直す。

### 段階2：必要になったら

- サイト上で修正する画面。複数人で直すようになったら、データの置き場所を DB に移す（部分一致の検索がしやすい PostgreSQL（RDS）、または DynamoDB）。
- 視聴率の推移のグラフ。

## 分析の運用（案）

- 分析は video_analyzer と同じ分析用PC で行い、結果を S3 に上げる。
- 毎日の分析（平日 18:00〜翌6:00、金曜 18:00〜月曜 6:00）と重ならない、平日 6:00〜18:00 に流す。
- 最初に既存の126回をまとめて流し（OCR・文字起こしで40〜60時間、平日の日中だけで2〜3週間）、その後は新しい放送回が出るたびに1本ずつ。
- Gemini の料金は1本約0.2ドル（126本で約25〜30ドル）。

## 先に確認すること

1. **視聴率データ**：毎分視聴率の入手方法、形式、社内サイトに載せてよい範囲（契約データの可能性が高い）。
2. **完パケの秒と放送時刻の対応**：視聴率と重ねるために、完パケの秒を放送時刻（16:25 開始）に変換する。完パケに CM 枠が入っているので足し算で合う見込みだが、1回分は実際の放送と照らし合わせる。
3. **一般の方の情報の扱い**：出演時の同意の範囲で、社内 DB に名前・顔を残してよいか。アクセスできる人の範囲。
4. **動画の保存場所と費用**：126本で約300〜400GB。S3 標準で月数千円程度。ストレージクラスで下げられる。
5. **サムネの元画像**：完パケからの切り出しはワイプやテロップが重なるので、制作側の元画像があれば差し替えたい。

# チョコサムまとめサイト 要件と引き継ぎ事項

閲覧用サイトを作る人（別リポジトリで作業する人・Claude）向け。2026-11-19 時点で、分析側で決まったこと・分かったこと・決まっていないことをすべてまとめる。
分析の詳細は `findings.md`、データの形は `data_model.md`、AWS 構成は `site_plan.md`、ジャンルの定義は `genre_rules.md`。

---

## 1. 何を作るか

**「超町人！チョコレートサムネット」の全放送回を、超町人（取材された一般の方）単位で一覧・検索できる社内向けサイト。**

- 番組：メ〜テレ制作のバラエティ。毎週日曜 16:25〜17:25 放送（放送日はスレートで確認済み）。MC はチョコレートプラネット（長田庄平・松尾駿）。
- 1回の構成：ロケ地（市区町村）が回ごとに決まっていて、タレント（サムネハンター）が街で一般の方に声をかけ、その人をサムネにする。1回あたり超町人は約7〜10組。最後にその回の No.1（MVS / MVC）を発表。
- 規模：放送回は #1〜#126（今後も増えるが頻度は低い）。超町人は全体で約1,100組の見込み。

### 1画面で見られるようにしたい情報（超町人1組ごと）

| 項目 | data.json のキー | 備考 |
|---|---|---|
| サムネ画像 | `thumbnail` | 無い人もいる（約1割） |
| サムネの文言 | `thumbnail_copy` | 例「若きチアダンサー 全米を魅了」 |
| 名前・年齢 | `names` / `ages` | 夫婦・家族は1組に複数人。名前が出ない人もいる |
| 肩書・小見出し | `title` | 番組右上のテロップ |
| 特徴（ジャンル） | `genres` | 配列。空配列＝該当なし。定義は `genre_rules.md` |
| ロケ内容の概要 | `summary` | 2〜3文 |
| 取材場所 | `place` | 店名や駅名 |
| 取材タレント | `talents`（名前）＋ 回の `talents[].group`（コンビ名） | |
| 放送回・放送日・ロケ地 | 回の `episode` / `broadcast_date` / `pref` / `city` / `area` | |
| その回の No.1 か | `is_top` | |
| 放送区間 | `start_sec` / `end_sec` | 動画内の秒。将来の動画再生・視聴率で使う |

### 検索・絞り込み（必須）

- 名前（部分一致。将来はよみでも）
- 特徴（ジャンル）：複数選択。フードの細分類（海鮮・肉・麺 など）でも絞れる
- 放送回・放送日（期間）
- ロケ地（都道府県・市区町村・エリア）
- 取材タレント
- フリーワード（概要・肩書・サムネの文言）

### 画面の案（決まってはいない）

- 一覧：サムネのカードを並べる。フィルタは横か上
- 超町人の詳細：上の全項目、同じ回の他の超町人へのリンク
- 放送回の詳細：ロケ地、タレント、放送日、その回の超町人の一覧（放送順）、No.1
- タレント別・ロケ地別の一覧

## 3. データの取り方（サイト側から見て）

- **本番**：`s3://chocosamu-data/site/data.json` と `site/thumbs/<回3桁>/thumb_XX.jpg`。サムネのパスは data.json からの相対パス（例 `thumbs/004/thumb_02.jpg`）。
- **開発**：`sample_data/site_data/` に同じものがある（5回・36組）。S3 につながなくても画面を作れる。
- データの形：`data_model.md`。サイズは全回で約1MB の見込みなので、**ブラウザで全部読み込んで、検索もブラウザ内で行う**前提で十分。
- 更新頻度：分析用PCで回を追加・修正したときに `build_site_data.py` → `upload_results.py site` で data.json を丸ごと差し替える。差分更新の仕組みは無い。
- 5回分（#02・#04・#40・#80・#126）だけ上げ済み。残りは分析用PCで順次処理する（平日の日中だけ動かすので、全回そろうまで2〜3週間）。

## 4. 守ること（セキュリティ・個人情報）

- **一般の方の名前・顔・年齢を扱う。ログインした社内の人だけが見られること。** URL を知っていれば誰でも見られる構成にはしない。
- `chocosamu-data` は非公開（パブリックアクセスをすべてブロック）。**公開設定やバケットポリシーで `Principal: "*"` を入れない。** サイトからは CloudFront の OAC 経由で `site/*` だけを読む。
- サンプルデータ（`sample_data/`、5回分の実データ）はリポジトリに入れている（2026-11-19、リポジトリが非公開のためユーザー判断）。**リポジトリを公開しない・外部に共有しない。** 全回分の data.json はコミットせず S3 に置く。スクリーンショットを外部に出すときも注意。
- 出演者の同意の範囲で社内 DB に残してよいかは、制作側に確認中（`findings.md` の最後）。

## 6. データの品質（表示側で気をつけること）

- **名前は人の確認が必要。** 名前テロップの画像を Gemini で読んでいるが、珍しい字は外れる（例：「桒山」を「葉山」）。`name_note` にふりがなや迷った候補が入るので、詳細画面か管理用の表示で見られると確認しやすい。確認用の名前テロップ画像は `s3://chocosamu-data/results/<回3桁>/name_frames/`。
- **ジャンルは判断がぶれる。** ルールに判断例を足して詰めている途中。未決定のもの：#40 の金魚すくい社長（アスリートか）、#40 の大学生アスリート（スーパーキッズか両方か）。`genre_reason` に根拠が入っている。
- **`id`（例 `004-02`）は作り直すと変わることがある**（回の中の放送順）。お気に入りやコメントなど、人のデータを id に結びつける機能を作るなら、安定した ID の仕組みが先に要る。
- `mc` の書き方が回によって違う（「チョコレートプラネット」と「長田庄平・松尾駿」）。表示に使うなら固定値でよい。
- サムネは完パケから切り出しているので、下の左右の角にスタジオのワイプが重なる。回によってはタイムコードやテロップも重なる。各回のフォルダに**制作側の配信用サムネ画像**（番組全体のサムネ）があり、元画像に差し替えられるかは確認中。
- `summary` はテロップとナレーションの事実だけで書かせている。
- サムネが無い超町人（`thumbnail` が空）も一覧に出す。

## 7. 動画と視聴率（段階3・4のための情報）

- 動画は分析用PC `D:\Projects\チョコサム分析\過去動画\過去回\#NN\` にだけある（元は Dropbox）。S3 には上げていない。費用の試算は `site_plan.md`。
- 動画は2種類：
  - **完パケ**：約59〜60分。CM 枠5か所が黒（各約2分）。秒＋16:25 でほぼ放送時刻になる。
  - **配信版**：約47分。CM を抜いたもの。大半の回はこちら。「_黒なし」付きとなしがあり、**「_黒なし」でない方を使う**（ユーザー指定）。両者の差は数秒。
  - どちらの版かは長さで判定できる。`start_sec` / `end_sec` はその回で分析に使った版の秒なので、**版の情報を data.json に足す必要がある**（未対応）。
- 配信版の秒を放送時刻に戻す手がかり：各回のフォルダの `〇〇_CM.txt`（CM の挿入位置。例 `00;07;43;00`）と CUE シート（xlsx）。
- 視聴率：`bangumi-info` の `rating/{yyyymmdd}_consolidated.xlsx` を、視聴率ダッシュボードがブラウザから読んでいる。チョコサムの毎分視聴率がそこに含まれるか、形式、社内サイトに載せてよいかは**未確認**。

## 8. 各回のフォルダにある、使えそうな資料

`過去回\#NN\` には動画のほかに次が入っている（回によって有無は違う）。サイトの補足情報や、分析結果の確認に使える。

- CUE シート（`...CUEシート【決定稿】.xlsx`）：放送の進行表
- `〇〇_CM.txt`：CM の挿入位置
- 配信用テキスト（`...配信用テキスト.docx` / `...番組内容.docx`）：TVer 等向けの番組概要
- 配信用サムネ画像（jpg/png）：その回全体のサムネ

# 調査で分かったこと（2026-11-18〜19）

対象: #01（別PCで調査）、#02（Dropbox の元動画が約14分で途中まで）、#04、#40、#80、#126。完パケ、1920×1080、約59〜60分。

## 番組の構成

1. 冒頭にスレート：タイトル（＝ロケ地。例「愛知・長久手市編」）、放送日、放送時間（16:25〜17:25）。**動画の先頭とは限らない**（#02 は約1分15秒後）。
2. サムネハンター（取材タレント）の紹介カード。MC はチョコレートプラネット（スタジオのワイプ）。
3. 超町人ごとに **ロケ VTR → スタジオで金の額縁に入ったサムネを発表** を繰り返す。
4. 最後にその回の No.1（MVS / MVC）の発表。

- 左上にタイムコードが焼き込まれている（#126 では額縁の中にかかる）。
- CM 枠が5か所あり、129〜144秒の黒。
- 超町人ごとに、右上に小見出しテロップ（例「初セントレア 職業柄あまり遠出ができない」）、下に「名前さん(年齢)」のテロップ。名前が出ない人もいる。

## 項目ごとの精度

| 項目 | 取り方 | 精度 |
|---|---|---|
| サムネ画像 | `find_thumbnails.py`（上の帯の色＋左右の金の枠の色） | ✅ #04〜#126 で発表画面のデザインは同じ。5回とも誤検出・見落としなし |
| サムネの文言 | サムネ画像を Gemini に渡して読ませる | ✅ 正確（OCR では崩れる） |
| 放送日 | OCR のスレートからプログラムで読む。年が欠けたら日曜になる年を計算 | ✅ 5回とも正しい。**Gemini に任せると月を取り違えた**（#80） |
| 回の番号 | ファイル名 | スレートには出ないことが多い |
| ロケ地 | スレートと「今回の舞台は〜」 | ✅ 都道府県・市区町村・エリアの3列 |
| 取材タレント | 冒頭の紹介カード | ✅ 名前とコンビ名を分けて保存 |
| 名前・年齢 | **名前テロップの画像**を Gemini に読ませる（OCR で「〜さん(〇歳)」が読めた時刻の画面下半分） | ○ OCR だけより大きく改善（例：加納真史・清水莉緒・紬七は画像で正解）。珍しい字（「桒山」）は外れる。ふりがなを注記に出すので人が確認する |
| 概要 | Gemini（OCR＋文字起こし） | ○ 2〜3文。テロップとナレーションの事実に限定 |
| 特徴（ジャンル） | Gemini（`docs/genre_rules.md`） | △ 判断例を足すたびに改善。最終確認は人が行う前提 |
| 開始・終了秒 | Gemini（小見出しの切り替わり） | ○ 目で全件は確認していない |
| No.1 | Gemini | ✅ 5回とも正しい |
| 文字起こし（Whisper） | 補助 | △ ナレーションは読める。ロケの会話は聞き間違いが多く、無音部分に「ご視聴ありがとうございました」と出る |

## 残っている課題

- **名前の確認**：人が `rows/<回>/name_frames/` の画像と照らし合わせて直す仕組みが要る。ふりがなは今は注記の文章に入っているので、「よみ」の列として出させると検索にも使える。
- **ジャンルのぶれ**：プロンプトを変えると、関係ない人の分類が動くことがある（温度0で同じプロンプトならほぼ固定）。新しい判断例を足したら、過去の回も作り直して差分を確認する。
- **超町人と演出の区別**：額縁入りの画像はすべて「サムネ」として検出される。超町人でない演出が額縁で出た場合は、Gemini が行に割り当てないことで除く（5回では該当なし）。
- **サムネの画質**：完パケから切り出すので、下の左右の角にワイプ、#126 ではタイムコードやスタジオのテロップが重なる。サイトに載せるなら制作側の元画像があるか確認したい。
- **OCR の出力に位置がない**：開始秒・終了秒・テキストだけ。今は文の形（「〜さん(〇歳)」）で名前テロップを見分けている。

## 処理時間と料金（分析用PC：GPU 24GB）

| 処理 | 1本 | 126本 |
|---|---|---|
| サムネ検出 | 3分前後（CPU） | 約6時間 |
| OCR＋文字起こし | 15〜30分（GPU） | 40〜60時間 |
| Gemini（2.5-pro、画像込み） | 約0.2ドル・1〜2分 | 約25〜30ドル |

GPU なしの普通のPCでも動くが、OCR（PaddleOCR）と Whisper（small）が CPU になるため、1本あたり数時間かかる見込み（未計測）。

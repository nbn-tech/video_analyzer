# サムネット分析（検討中）

バラエティ番組「超町人！チョコレートサムネット」の動画を分析して、次の情報をまとめたデータベースと、それを一覧で見られる社内サイトを作れるか検討している。

- 第●回のオンエア（回・放送日・エリア）
- 超町人（名前・年齢・肩書）と、その人のサムネ画像
- 取材に行ったタレント
- 動画（超町人ごとの開始・終了の秒数）

> **このフォルダは一時的な置き場所です。** video_analyzer とは別のプロジェクトなので、本格的に始めるときは新しいリポジトリに移す。それまでは、分析用PCと共有するためにここに置いている。毎日の分析（`worker.py` / `backfill.py`）からは一切呼ばれない。

## ここまでに分かったこと（2026-11-18、#01 で調査）

サンプル: `#01.mp4`（完パケ、59分、1920×1080）

### 番組の流れ

1. 冒頭にスレート：「#1 名古屋市大須エリア編」「放送日 2023年10月8日(日)」「16:25〜17:25」
2. タレントの紹介：尾形貴弘（パンサー）・峯岸みなみ。MC はチョコレートプラネット（スタジオのワイプ）
3. 超町人ごとに **ロケの VTR → スタジオでサムネ発表** を繰り返す
4. 最後に MVS（大須の No.1 超町人）の発表

動画の特徴：
- 左上にタイムコードが焼き込まれている
- CM 枠は5か所あり、どれも129〜144秒の黒

### 各項目が取れそうか

| 項目 | 映像で見えたもの | 確認できた範囲 |
|---|---|---|
| **サムネ画像** | 発表画面は毎回「銀色の背景＋金の額縁」で、5〜11秒表示 | ✅ **自動で検出して切り出せた**（11枚すべて、誤検出なし） |
| 回・放送日 | 冒頭のスレート | 👀 目で確認しただけ |
| 超町人の区切り | 右上の小見出しテロップ（例「大須を徘徊するドMイケマッチョ」）が人ごとに切り替わる | 👀 目で確認しただけ |
| 名前・年齢・経歴 | 「井上 雅菜さん(33歳)」のようなテロップ。出ない人もいる | 👀 目で確認しただけ |
| 取材タレント | 冒頭の紹介カード。誰が誰を取材したかは、服の色（尾形＝赤、峯岸＝緑）や発言で分かる | 👀 目で確認しただけ |

- ✅：スクリプトで自動化して確かめた
- 👀：書き出した画像を人（Claude）が見て、テロップが映っていることを確かめた。**今のシステムの OCR で読めるかはまだ確かめていない**

補足：
- **全員にサムネがあるわけではない。** 井上さんと、ジェットコースターの男性（38〜43分ごろ）は発表画面が見つかっていない。データは「超町人1人に対してサムネは0枚以上」という形で考える。
- **サムネの下の左右の角には、MC のワイプが少し重なる。** 制作側に元の画像ファイルがあれば、そちらの方がきれい。

### サムネ検出のやり方（`find_thumbnails.py`）

- 0.5秒ごとに、額縁より上の帯（x720〜1900, y0〜80）を 59×4 ピクセルに縮める。
- それを #01 の発表画面から取った基準（`reveal_ref.rgb`）と比べ、次の両方を満たす区間を発表画面とみなす。
  - 平均色差が 25 未満
  - 彩度が 30 未満
- 額縁の内側（`crop=1430:822:248:136`）を、区間の真ん中のフレームで切り出す。
- CM をはさんで同じサムネが2回出ることがあるので、見た目が同じものは1枚にまとめる。
- ffmpeg と Python の標準ライブラリだけで動く（GPU・AI 不要）。
- 映像が止まる区間を探す ffmpeg の `freezedetect` は、ワイプが動いているので使えなかった。

## 分析用PCでやること（次のステップ）

**目的**：今のシステムの Whisper（文字起こし）と PaddleOCR（テロップ読み取り）を #01 にかけて、名前・回・小見出し・タレント名を自動でどこまで読めるかを確かめる。

### いつやるか

**毎日の分析が止まっている平日 6:00〜18:00 に実行する。** GPU の取り合いを避けるため。

- 平日：18:00〜翌6:00 は毎日の分析が動いている
- 土日：金曜 18:00〜月曜 6:00 は通しで動いている → **土日はやらない**
- 処理時間の目安は 20〜40分

始める前に、毎日の分析が止まっていることを確認する。何も表示されなければ OK。

```powershell
Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
  Where-Object { $_.CommandLine -match 'backfill\.py|worker\.py' } |
  Select-Object ProcessId, CommandLine
```

一時ファイルを書く `A:\tmp` の空き容量も確認する。OCR は1秒ごとの画像を書き出すので、59分の動画で約3,500枚・数GBになる。

```powershell
Get-PSDrive A
```

### 手順

1. `git pull` でこのフォルダを取ってくる。
2. 動画 `#01.mp4` を分析用PCの任意の場所に置く。**リポジトリの中には置かない。** `.gitignore` で `*.mp4` は除外されるが、念のため。
3. video_analyzer の仮想環境で実行する。

```powershell
.venv\Scripts\python samunet\samunet_probe.py "D:\chocosamu\#01.mp4" D:\chocosamu\probe_out
```

パスは実際の場所に変えること。

### 守ること

- **`worker.py` / `backfill.py` では動かさない。** これらで動かすと結果が S3 の `results/`・`athena-data/` に書き込まれ、ダッシュボードのデータに混ざる。`samunet_probe.py` は S3 に何も書かず、Gemini も呼ばない（料金なし）。
- **スクリプトの名前に `worker` / `backfill` を入れない。** 平日 6:00 の `stop_worker.ps1` が、名前でプロセスを探して止めるため。

### 持ち帰るもの

`probe_out` に次の2つができるので、検討用のPCに持ってくる。

- `audio_rows.json`：Whisper の文字起こし（開始秒・終了秒・テキスト）
- `ocr_rows.json`：OCR のテロップ（開始秒・終了秒・テキスト・位置）

持ち帰ったら、名前テロップ・スレート・小見出しがどこまで正しく読めているかを、目で確認した内容と照らし合わせる。

## その後の予定

1. OCR と Whisper の結果を確かめる（↑）。
2. Gemini に「回 → 超町人 → サムネ」の形の JSON を作らせるプロンプトを試す。
3. 他の回でも、サムネの検出（額縁のデザイン・位置）が同じように通るか確かめる。
4. 新しいリポジトリに移して、データベースと社内サイトを作る。
   - サイトは社内用。一般の方の顔写真と名前を扱うので、ログインは必須。

### 制作側に確認したいこと

- 他の回も同じ発表画面のデザインか
- サムネの元の画像ファイルは残っているか
- 全部で何回分あるか

## 新しいリポジトリに移すときに持っていくもの

- **このフォルダ一式**：`find_thumbnails.py`、`reveal_ref.rgb`、この README の調査結果
- **video_analyzer から流用するもの**（`app/services.py`）
  - Whisper の文字起こし：`transcribe_video`、`_segment_rows`
  - OCR のテロップ抽出：`_extract_ocr_rows` とそのフィルタ・まとめ処理
  - Gemini の JSON リトライ：`_generate_json_with_retries`。長い動画の分割処理（`_segment_corners_chunked`）もあわせて
- **流用しないもの**
  - ニュース向けのコーナー分割プロンプト（11分類）
  - 放送時間帯フィルタ
  - Athena 用の Parquet の形
  - SQS で常に待ち受ける仕組みと、運用スケジュール
- **注意点**
  - `services.py` は一時フォルダが `A:\tmp` 固定になっている（分析用PC専用）。新しいリポジトリでは設定で変えられるようにする。
